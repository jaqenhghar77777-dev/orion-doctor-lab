# Current stock Doctor rehearsal

The manual corrective workflow runs the stock Doctor CLI once and tests the seven-file handoff in a fresh state tree. The strict verifier records its own result. The usability gate permits only the three observed main-agent session comparisons with their recorded row counts. The input and output artifacts contain private sanitized content. The phone check and channel setup follow the steps in [the reviewed plan](USABILITY_PLAN_v1.md).

The phone dispatcher preserves the original strict report and stores a fresh artifact key in its private receipt directory. The key is registered as a repository Actions secret for this run. The runner encrypts both the input handoff and any returned state with OpenSSL AES-256-CBC and PBKDF2 before uploading them. Check the independently recorded plaintext SHA-256 after decryption and before extraction. Only the metadata report is readable without the key. After the run, the repository secret can be removed while keeping the phone key for download. A dispatch error after secret registration requires checking the existing run and receipt before any retry.
